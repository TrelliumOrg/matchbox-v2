300ms, fresh
  • 300ms per figure, easing cubic-bezier(.2,.8,.2,1). matchbox-v3 uses 380ms for NumberFlow; the homepage uses 300ms, the owner's ceiling.
  • Only digits that changed move. Every changed digit of every changed figure starts at the same moment, no stagger.
  • Up when the value grows, down when it falls. Each digit box fades its top and bottom 16% with a mask.
  • No colour change, no flash, no scale, no blur. NumberFlow: transformTiming and spinTiming 300ms with the easing above, opacityTiming 200ms, trend from the sign of the change.
Words, pictures, the note
  • Gauge and validator names change with torph TextMorph, 300ms, cubic-bezier(.19,1,.22,1).
  • Gauge pictures, type icons and coin stacks crossfade, opacity only, 200ms ease-out.
  • "As of 14:05" fades in and out, opacity only, 200ms.
  • "Not available" to a value: 200ms fade, no roll.
  • Units ("veBTC", "veMEZO", "BTC", "txns") never animate.
No layout movement
  • Tabular numerals on every live figure: font-variant-numeric: tabular-nums.
  • Fixed heights: gauge rows 62px (58 phone), block rows 56px (54 phone), headline line box 52px (44 phone), stat line box 36px (32 phone).
  • Right aligned values sit in their own grid column and grow to the left. The name column absorbs it.
  • The note's space is always there: visibility, never display.
  • A figure that gains a digit grows into free space on its own line. Nothing beside it moves.
Reduced motion
  • With prefers-reduced-motion: reduce, values just change. No roll, no morph, no crossfade, no fade on the note.
  • The countdown still updates every 60000ms.
  • Same rule when a card is off screen at swap time: the value just changes, so nobody scrolls into a roll.
When to fetch
  • First paint never waits for a request: the snapshot is in the HTML.
  • One fresh request after first paint, on idle, at most 1000ms after load, never before the LCP element paints.
  • Timeout 5000ms. A failure or timeout is state 3.
  • Refresh: Pro figures every 60000ms, Matchscan stats every 60000ms, latest blocks every 30000ms. Only while the tab is visible and the card is in the viewport. Coming back, refresh at once if older than the interval.
  • At the epoch boundary the Pro figures refetch.
The cache
  • The server renders every live figure from the latest snapshot, with its snapshot time.
  • A scheduled job refreshes the snapshot every 60000ms and it is served stale while revalidating, so first paint has values in normal operation.
  • The fresh response has the snapshot's shape. One request covers both cards.
  • Snapshot older than 300000ms and no fresh data: show "As of".
Never on this page
  • Skeletons, spinners, "Loading" or empty boxes, even for a moment.
  • $0, 0 or a dash standing in for a missing value. Missing reads "Not available".
  • Count-up from zero on first view. matchbox-v3 headline count-ups do not run on the homepage, because the cached value is already right.
  • Live dots, "updated 12s ago" lines, colour flashes on change.
  • Anyone's own data: no wallet, lock, ballot or address. Every figure is protocol wide.
